# План подготовки проекта и публикации на GitHub Pages

## 1. Анализ готовности проекта к GitHub Pages

### Можно ли захостить текущий проект на GitHub Pages с полным функционалом?
**Да, на 100%!** 
Текущее приложение представляет собой полностью автономное клиентское Single Page Application (SPA):
- Алгоритм линейного раскроя (перебор вариантов, КИМ, учет деловых остатков) полностью исполняется в браузере.
- Импорт файлов склада и заказов (XML, CSV, TXT) и их анализ выполняются на клиенте через браузерный `DOMParser`.
- Экспорт результатов в Excel (`.xlsx`), XML и CSV генерируется на лету через встроенную библиотеку `SheetJS` без обращения к серверу.
- Печать карт раскроя и отчетов работает через нативный интерфейс печати браузера.

## 2. Сравнение способов деплоя (Что лучше для вашего варианта)

| Способ | Как работает | Плюсы | Минусы | Рекомендация |
| :--- | :--- | :--- | :--- | :--- |
| **GitHub Actions (CI/CD)** | Вы просто делаете `git push` своего исходного кода. Сервер GitHub сам запускает установку библиотек, сборку `npm run build` и публикует сайт. | <ul><li>Полная автоматизация (один раз настроили — и забыли)</li><li>В репозитории хранится только чистый исходный код, без мусорных сборок</li><li>Любые правки сразу попадают на сайт</li></ul> | Требуется файл конфигурации `.github/workflows/deploy.yml` (мы его создадим) | **Идеально (Рекомендуется)** |
| **Пакет gh-pages** | Вы локально компилируете проект командой `npm run build`, а затем отдельной командой отправляете скомпилированную папку `dist` в специальную ветку `gh-pages`. | Не требует настройки Actions | <ul><li>Нужно каждый раз вручную выполнять деплой с компьютера</li><li>При забытом деплое сайт не обновится</li></ul> | Менее удобно для постоянной работы |

**Выбор:** Настроить **GitHub Actions**. Это современный промышленный стандарт GitHub: вы просто загружаете код в репозиторий, а GitHub Pages разворачивается автоматически за 1–2 минуты.

## 3. Что необходимо доработать в проекте

### Шаг 1. Настройка базового пути в `vite.config.ts`
По умолчанию Vite ожидает, что сайт открывается в корне домена (`/`). Но на GitHub Pages адрес сайта обычно имеет вид:
`https://<ваш-логин-github>.github.io/<имя-репозитория>/`

Если путь не настроить, браузер будет искать стили и скрипты по адресу `https://<ваш-логин-github>.github.io/assets/...` и выдаст белый экран (ошибка 404).

**Решение:**
В `vite.config.ts` настроим:
```ts
base: './' // или process.env.BASE_URL || './'
```
Относительный путь `./` делает проект универсальным: он будет работать с **любым именем репозитория**, а также при желании сможет открываться даже локально из папки `dist/index.html` без веб-сервера.

### Шаг 2. Создание GitHub Actions Workflow (`.github/workflows/deploy.yml`)
Создадим автоматический сценарий для GitHub:
1. Запускается при каждом коммите/пуше в ветку `main` (или `master`).
2. Разворачивает виртуальную машину с Node.js 20.
3. Устанавливает зависимости (`npm ci`).
4. Собирает проект (`npm run build`).
5. Загружает артефакт папки `dist` и автоматически разворачивает его на GitHub Pages.

### Шаг 3. Добавление скриптов сборки и проверки в `package.json`
Убедимся, что скрипты `"build": "vite build"` и `"preview": "vite preview"` настроены корректно, а также добавим проверку типов `tsc --noEmit`.

### Шаг 4. Добавление файла `.gitignore`
Чтобы при создании репозитория вы случайно не загрузили тяжёлую системную папку `node_modules` или временные файлы сборки `dist`.

## 4. Пошаговая инструкция для вас: как создать репозиторий и запустить сайт

После того как проект будет подготовлен, для публикации вам понадобится выполнить простые шаги:

1. **Создать репозиторий на GitHub**:
   - Зайти на [github.com](https://github.com) и нажать **New repository**.
   - Назвать репозиторий, например: `linear-cutting-optimizer` (или любое другое название).
   - Сделать его **Public** (для бесплатного хостинга GitHub Pages).
   - Не добавлять README или .gitignore (они уже будут в проекте).

2. **Загрузить проект в репозиторий**:
   В терминале проекта выполнить команды:
   ```bash
   git init
   git add .
   git commit -m "Initial commit: Linear cutting optimizer"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<имя-репозитория>.git
   git push -u origin main
   ```

3. **Включить GitHub Pages в настройках репозитория**:
   - Открыть страницу репозитория на GitHub -> вкладка **Settings** (Настройки).
   - В левом меню выбрать **Pages**.
   - В выпадающем списке **Source** выбрать: **GitHub Actions**.

4. **Готово!**
   GitHub Actions автоматически выполнит сборку, и через 1-2 минуты во вкладке **Actions** появится зеленая галочка, а сайт будет доступен по ссылке:
   `https://<ваш-логин>.github.io/<имя-репозитория>/`

## 5. План выполнения изменений в коде

1. Обновить `vite.config.ts`: задать `base: './'` для поддержки субдиректорий GitHub Pages.
2. Создать каталог `.github/workflows/` и файл `deploy.yml` для автоматического деплоя.
3. Проверить и дополнить `.gitignore` (исключить `node_modules`, `dist`, `.env.local`).
4. Создать файл `README.md` с описанием возможностей проекта и инструкцией по развертыванию.
5. Проверить сборку через `compile_applet` (`npm run build`), чтобы убедиться в отсутствии ошибок при упаковке в production-режим.
